# Regional mino ledger

This is **offline simulation telemetry**, not a coaching rule or a new live-page
panel. It accounts for actual placed cells, cleared cells and board-resident
mass in Left columns 1–4, Center 5–7 and Right 8–10. A piece spanning regions is
counted cell by cell. No search, ranking, resource quota or Reset classifier is
added. The planner receives no source-token or original-bag IDs.

## Run it

Use pinned Node 24.22.0 from the repository root:

```sh
# Analyze an existing episode without running the planner.
npm run minos:st -- --episode test-results/simulation/RUN/empty-10331

# Choose a new, nonexistent output directory. Its parent must already exist.
npm run minos:st -- --episode EPISODE_DIRECTORY --out NEW_DIRECTORY

# Reconstruct the exact recorded prefix, including its HOLD inventory.
npm run minos:st -- --episode EPISODE_DIRECTORY --prefix-locks 7 --windows 7,14,28

# For a new simulation, export only AFTER every timed episode has finished.
npm run sim:st -- --preset quick --mino-ledger
```

Each analysis writes `ledger.json`, `locks.csv`, `bags.csv` and `windows.csv`.
The default destination is a new timestamped subdirectory of the episode.
Existing output directories are never replaced. The source input and trace
remain read-only. `--mino-ledger` also records export results/errors in the run
manifest; an export error exits nonzero without rewriting simulation outcomes.
It is separate from in-search `--usage-telemetry` and has no per-decision cost.

## What is counted

For each region, every lock checks:

`new board mass = previous board mass + placed cells - cleared cells`.

Every complete line removes exactly 4 Left, 3 Center and 3 Right cells. The four
new cells are assigned to their source token **before** all actual cleared rows
are removed, then surviving owners shift with the rules kernel. This handles
nonadjacent clears, newly placed cells cleared immediately, imported full rows,
and the final top-out placement. Clear credit belongs to the original owner of
each removed cell, not to the piece that caused the clear.

`remaining` always means cells currently on the board. Active, held and preview
pieces are separate inventory and do not inflate placed or remaining mass.
`placedByPiece` reports raw I/J/L/O/S/T/Z regional cell totals; it does not guess
whether a T or Z was strategically diverted or whether a Z/J construction was
intended. `massPerColumn` divides regional mass by 4/3/3; it is not skyline height
and does not describe holes, access, parity or supported geometry.

Rolling windows default to 7, 14 and 28 **locks**, not source bags. They retain
their own starting mass; a negative net is valid when older cells are cleared.
Early windows explicitly say `partial`. A seven-lock window is not generally one
original seven-bag, especially when a piece is held across a bag boundary.

## Original-bag identity and honest unknowns

The evaluator can reconstruct source bags only when the input matches the
supported generator exactly: schema, scenario, RNG version, seed, regenerated
initial public state, the entire private source and its original input hash.
The generation span is recovered from the source length, separately from the
evaluation cap. Historical inputs generated for 70 locks but later evaluated
with cap 150 therefore retain their identity. Merely supplying a seed, matching
piece letters or attaching a claimed provenance object is insufficient.

For generated empty starts, the initial active piece and six preview pieces
form the first known source bag. Tokens then follow actual draws and every
HOLD swap, including repeated unlimited HOLD and swaps between identical piece
types. Only active, held or actually revealed pieces become report tokens;
unobserved future piece types are never exported by the ledger.

For the generated stable fixture, **all initial board cells, active, held and
preview tokens stay unknown**. The verified generated continuation can begin
partway through a source bag. `priorUnattributedPieces` preserves that missing
prefix; it is not silently assigned to initial tokens with matching letters.
Bag IDs are relative to this recorded input, not recovered global IDs from an
original human game. Other imports, missing contracts, tampered streams or
unmatched hashes use an explicit unknown-origin bucket. That bucket is not one
seven-bag. Region totals still reconcile without source-bag knowledge.

Known provenance here is an **evaluator fact**, not necessarily information the
public bag model or coach could know at that moment. The pure ledger imports
only the rules and bag kernels. Generator verification is a separate evaluator
wrapper; no planner search or decision is run. Optional `makeInput(...,{withOrigins:true})`
metadata leaves default generated bytes, hashes and RNG draws unchanged.

These distinct bag states prevent misleading completion claims:

- `sourceCoverageComplete`: all seven source tokens are known, with no missing
  prefix. They may still be active, held or in preview.
- `allTokensLocked`: all seven known source tokens have actually locked.
- `boardDepleted`: a complete, fully locked bag has no cells remaining on board.
- `pendingAndLocked`: separate locked, active, held and preview token counts.

## Verification boundary

The analyzer replays actual rules/actions, draw counts, action hashes, lock
cells, clear rows, before/after public observations and cell ownership. It
checks regional and per-source-bag mass conservation. A corrupt or out-of-order
record is rejected rather than repaired. Inputs are bounded to 2000 locks and
20,000 private pieces; input and trace files are each limited to 64 MiB.

`coverage.summaryReconciled` means the terminal summary's input identity, cap,
lock/line counts, final public observation and basic stop/censor consistency
match the replay. It does **not** certify every policy metric, retained goal,
planner request metadata, strategy choice or the reason an abstention happened.
A trace without a terminal summary, or an explicit `--prefix-locks` selection,
is labelled `verified-recorded-prefix`, not a fully reconciled episode. Prefix
rewind is an offline reconstruction, not a new live Undo/Redo feature.

The JSON binds input/trace byte hashes, analysis dependency hashes, repository
commit/dirty state and Node version. Keep the original simulation evidence
separate: replaying existing actions is not a fresh timed policy comparison.

## A concrete HOLD example

On retained development stream 502923646, the earlier opening route completes
its original first bag only at lock **11**. At lock 6 it holds a J from bag 1
while another J from bag 2 is active. The narrowed opening route completes the
first bag at lock **7**. Its first seven locked source slots are
`1, 3, 4, 5, 2, 7, 6`, not draw order.

Their original first-bag allocations are Left/Center/Right **13/15/0** versus
**18/10/0**, each 28 cells. At the common lock 25:

| Recorded route | Placed L/C/R | Cleared L/C/R | Remaining L/C/R |
| --- | --- | --- | --- |
| Earlier route | 52 / 44 / 4 | 0 / 0 / 0 | 52 / 44 / 4 |
| Narrowed opening | 46 / 40 / 14 | 16 / 12 / 12 | 30 / 28 / 2 |

The narrowed route ends at lock 68 with placed **106/91/75**, cleared
**56/42/42**, remaining **50/49/33**. These are measured material flows, not proof
that one regional imbalance caused its eventual abstention. They do not justify
a fixed per-bag placement target. Only over a sufficiently long bounded-mass
run does full-row clearing imply an average **4:3:3** placement ratio.

## Tests

Eleven lightweight regression cases cover frozen generator hashes, original
bags through HOLD, same-type swaps, cross-region cells, old-owner clears,
nonadjacent/pre-full rows, stable partial bags, honest unknowns, prefix rewind,
top-out inventory, corrupt/terminal records and both export entry points. They
use real rules and retained/simple witnesses, not new planner searches. The
independent audit compares existing recorded streams against a separate
frozen-rules oracle; final revision-bound evidence is retained with the report.

The [compact validation record](st-regional-mino-ledger-results-2026-10-25.json)
binds clean ledger revision `56810bb3d6a211e44f62750a2b1bbc82279415c4`:

- 895 existing locks in ten episodes, 7,723 actions, 187 HOLD actions and 104
  clearing locks, with exact original-bag ownership and 2,685 rolling windows.
- 42 generated-input/default-byte/public-request equivalence controls.
- Eight separately labelled historical stable-start locks, preserving unknown
  initial ownership and verified partial future-bag boundaries.

These are independent accounting/replay checks, not new timed rollouts or a
strategy-success sample. Policy runtime is unchanged from the already-tested
narrowed opening source. The normal aggregate behavioral suite remains the
separate final repository gate.
