# Shared-state migration progress

This records implementation of the [shared obligation contract](st-shared-state-contract.md). The baseline is `022290b4f10917f6f1831a03c7c907f84f5d356a`. The existing monitoring-boundary fix on that baseline is unchanged. Work remains local until publication is separately approved.

## First checkpoint: current inventory and Center transitions

- `st-public-inventory.js` owns live identity assignment, active/HOLD/preview flow and the incremental public bag frontier. It has no old-piece table, action tape or generator access. A portable current snapshot is imported directly after shape/reference checks, without provenance replay.
- Legacy resource accounting consumes these subjects and retains its old historical allocation/pair archive while those consumers are migrated. At this first checkpoint the inventory was temporarily held by that compatibility layer. The second checkpoint below moves ownership to the real callers.
- The page controller no longer accumulates an `observed[]` draw history merely to recompute bag knowledge. Initial public knowledge is seeded once, each actual reveal advances it, and existing caller snapshots restore it on Undo.
- `st-center-obligations.js` updates current exact Center targets and diversion debts, returning this operation's creation, diversion, closure and pair effects separately. No closure archive is retained in its state. Actual accounting uses that reducer; projected routes share its geometry/payment facts while retaining their own lost-target admission diagnostics.
- Payment, diversion and invalidation remain distinct. A genuine replacement pays the pending and diverted facets once without inventing a second pair. Old resource-summary fields and coaching policies remain compatible.

Focused coverage includes HOLD age and original bags, unknown/deferred/forced supply, trusted inventory snapshots, invalid flows, immutable Undo branches, actual controller reveal/restart/Undo, exact Center payment versus diversion, loss, and same-state repeated cycles. New inventory tests cross 4,200 movement inputs and 700 locks without retaining past identities; the Center component returns to empty current state after each of 1,000 equivalent settlement cycles. These are component lifetime tests, not claims of long simulated survival.

Independent baseline comparisons found identical full resource summaries after 2,066 trial actions and 65 existing replay contexts. Separate frozen-source comparisons covered 142 actual locks and 109 full projected resource states, including S85/L86, Reset L37 and the translated pending-L continuation. Generated comparison scripts and evidence remain outside Git.

## Second checkpoint: caller ownership and compact notch state

The page controller and simulator now own the current public inventory. Each accepted input produces one bounded transition receipt containing the prior/next inventory, locked subject and newly revealed subjects. Resource accounting consumes that receipt rather than applying identity flow again. Receipts bind to the actual public boundary and revision; they are not a journal and are not stored inside the next inventory. Legacy resource replay uses the same adapter internally until its transport is replaced.

The caller checkpoints inventory directly for Undo. Session installation restores the imported live inventory, including public bag knowledge for partial origins, without turning a deduced next type into an invented original bag. Current inventory continues across the legacy accounting cap or an accounting failure; an executed legal move is not rolled back. New tests exercise copied/stale receipts, reused numeric IDs on a new Undo branch, real page and simulator flow, and continued draws after the existing action/lock limits.

`st-pattern-history.js` keeps its public API but emits compact version-2 notch checkpoints: current status, anchor, blocked rows and diagnostic source. Protected rows are derived from the current anchor. Live play no longer stores origin boards or a lock tape and no longer has the old 128-lock limit. The supplied current facts are trusted without proving their history; shape checks and future movement/strategy checks remain.

Old notch tapes remain a compatibility input. They still validate under their original finite contract, then session import/export and the next live update replace them with current facts. The outer session schema stays at version one with a versioned nested checkpoint; an older tape-only reader rejects the new payload rather than silently re-anchoring it. Full resource session accounting is still legacy/replay-backed.

Notch tests cover canonical TSD/quad translation, newly established phases, sticky broken facts, trusted import, invalid shapes, legacy tampering, page/Worker transport and Undo. A 1,000-lock manual O-only cycle retains fixed-size current facts beyond the former tape limit. Independent comparison found 375 identical phase results across 365 locks and ten legacy conversions. Newly added source files are included in simulation source hashes and the worker loader; missing/changed dependency hashes fail frozen-source binding.

## Third checkpoint: isolated S/L and opening account reducers

`st-sl-obligations.js` implements current same-bag counterpart consequences separately from production consumers. A consumed counterpart remains only while an unconsumed counterpart, exact Center target, unresolved first-bag decision or live caller reference can still distinguish it. Once those distinctions end, unresolved consequences move into fixed type/severity counters. Compaction is not payment. Operation-local classification effects preserve a newly uncertain identity even when it immediately becomes an aggregate, so later consumer migration can still distinguish inherited uncertainty from a new loss.

The component preserves the existing asymmetric S/L policies, foundation and first-bag exemptions, foreign-bag payment ordering, pending LO accommodation and exactly-once opening handoff rebase. Trusted snapshots validate their current shape and internal references without proving their history or consulting a board. No live-record count limit is imposed. Numeric representation failures are explicit rather than silently rounding or dropping a consequence.

`st-opening-obligations.js` implements temporary allocation/quality duties, the mandatory opening Z, a net conserved Z balance, sticky eligibility facts and only the active Reset duty. Each actual qualifying Left T credits one Z. Completion emits an effect and retires that Reset's temporary identity and inherited-covered-cell references; it does not award two more credits or retain an episode list. Current facts import directly. Current public identity and exactly-once delivery, Reset selection, unknown-origin observation diagnostics and historical display totals remain caller responsibilities.

These two components are deliberately **not loaded by the page, worker or simulator yet**. They are phase-three building blocks, not replacement planner authorities. Their tests compare canonical current facts against the old classifier over literal transitions and public replays, plus lifecycle size checks. Aggregate uncertainty cannot simply replace the old identity arrays in admission or beam keys. Those consumers and effect-based monitoring must migrate together before production compaction is enabled.

## Fourth checkpoint: one current factual transition entry point

`st-obligation-state.js` composes the Center, S/L and opening-account reducers with current notch/covered-repair facts and the existing observed D duty. It retains only those current consequences. Public positions, inventory, phase, selected plans, receipts and operation effects stay outside the envelope. Current JSON snapshots import directly after structural/reference checks, without proving their history.

The actual adapter consumes the controller's authentic one-operation inventory receipt. The projected adapter independently replays a finite legal witness and advances a cloned public inventory; it does not issue actual receipts. Both use the same factual transition. HOLD is processed before identifying the locked subject, including an old held piece and repeated HOLD. This initial projected adapter deliberately supports only already-observed, known-origin supply. Unknown or forced subjects and expanded previews fail explicitly rather than acquire invented identities or bags.

The shared transition applies exact Center payment/loss first, then S/L classification, then opening/Z/Reset consequences. Safety uses the existing notch and covered-repair rules. Observed non-D to D transitions create the same D duty as before; importing D geometry does not fabricate that observation. Handoff rebases S/L exactly once, without erasing Center duties or changing the Z account. Reset completion emits its factual effect and retires its temporary duty.

`resolve(current, {position, inventory})` reads one unified current status without storing another ledger. It exposes each component's known, unknown and unclassified facts, current targets and safety duties, with no historical capacity, retired identities or completed episodes. Missing or mismatched public context is an explicit error. Run termination, cap/censoring and coverage-through-lock metadata remain caller-owned.

This envelope is also **not loaded by production consumers yet**. It establishes a common factual path; it is not a route-admission implementation. A hypothetical baseline credit does not authorize an ordinary route to spend that credit. Pending-target loss, proposed L diversion, request-root uncertainty, Reset completion and other route-only consequences still need explicit consumer adapters. Unknown-origin diagnostic policy is not broadened here.

## Fifth checkpoint: shared admission predicates and current lifecycle adapter

`st-obligation-admission.js` now supplies the existing production admission predicates to midgame resources, ordinary planning and Reset. It distinguishes generic uncertainty from severe S accommodation, compares current exact uncertainty keys with the fixed request root, and detects the existing Reset-only known-to-unclassified or newly lost-target conditions. This is a consolidation of current policy, not a new prohibition on ordinary unclassified S/L. Exact keys deliberately refuse anonymous aggregates; the remaining route adapter must preserve the required current references or equivalent request-local effects before enabling production compaction.

`st-obligation-context.js` is an **unwired controller adapter**, not a second production ledger. It combines one current public inventory with the factual core and only two bounded opening-boundary facts: progress through the first seven locks and whether the first exact source pattern has been seen. It computes these boundaries from accepted locks, without relying on the old resource tape, elapsed identifier values or a supplied historical milestone. Actual transitions consume one authentic inventory receipt. If accounting fails after an executed move, inventory still advances and status becomes explicitly unavailable rather than silently reinitializing duties.

The adapter handles accepted handoff and Begin Reset markers, direct trusted paired import, current namespace collision checks and immutable caller snapshots/restore. Imports trust duties as supplied; they only reject contradictory current structure or consumed references that collide with a live/future inventory subject. Snapshot/restore supports the existing caller checkpoint model. It does not yet implement the proposed compact inverse-receipt Undo transaction, define a new checkpoint boundary or wire page/session transport.

Focused tests cover the production S85/L86 and Reset L37 distinctions, authentic visible-J repair, fixed-root replacement/reintroduction, unknown versus severe uncertainty, compact operation effects, source/lock-seven decisions, imported current identity collisions, receipt authentication, unavailable accounting, branch restoration and repeated current-state cycles. Full component replay comparisons use the independent original history classifier; matching current facts does not establish complete compact route admission.

## Sixth checkpoint: projected supply and fixed-root route assessment

`st-obligation-projection.js` now represents a finite hypothetical path separately from actual state. Observed subjects retain their public identities and original bags. Unknown or uniquely deduced subjects use a separate negative request-local namespace without invented bags, public reveals or actual receipts. The shared factual reducers handle exact synthetic Center payment and existing projected Reset credit, while actual imports continue to reject projection payloads. The prior observed-only `Core.project` API remains available for compatibility comparisons.

`st-obligation-assessment.js` keeps request permission separate from factual status. It records the fixed root's current duties and inherited uncertainty, then consumes current facts and operation-local effects. New or immediately compacted uncertainty keeps its identity within this finite request. Already anonymous root uncertainty stays in severity counts rather than acquiring fabricated identities. The adapter preserves lost-target and proposed-diversion overlays, original-duty comparison, root Z spending permission, T schedule/collision checks and Reset completion after its factual duty retires. Ordinary disclosure and Reset-specific loss rejection remain different policies.

`st-obligation-route.js` composes supply, factual projection, assessment and the same bounded source/first-seven-lock boundary used by the actual Context. Each child replays one exact public witness and leaves its parent unchanged. It includes ordinary finite resource-path checking, not the complete planner or repair-search interface. Projection state, effects, route permission and actual state remain distinct domains.

These modules are **unwired preparation for the authority switch**. They are not loaded by production page/Worker/simulator consumers. Focused cases include old HOLD, unknown identical-letter HOLD, forced supply, synthetic exact SL/LO payment, actual-import rejection, fixed-root identity replacement, immediate compaction, Reset completion/loss, authentic visible-J repair and global classic-script loading. Independent sequential comparisons check retained observed-supply prefixes against the frozen old resource engine, without future reveals or planner search.

Semantic comparisons intentionally exclude retired history from bindings: anonymous uncertainty must already be anonymous at the request root and remain unchanged; exact current/new identities and severity totals still match. Retired OJ/ZJ root bags are not reconstructed, because only SL/LO require those counterpart facts. An inactive completed Reset does not retain its old progress counter; an active-root request still preserves its completion result. These are explicit compact representations, not relaxations of route policy or proof that incidental history-sensitive beam membership stays identical.

## Seventh checkpoint: one search grammar and finite consumer adapters

`st-resource-search.js` extracts the existing repair and pending-L staging grammar once. Production `st-midgame-resources.js` delegates to it with the legacy factual backend. Ordering, bounded search, movement/access proofs, witness checking and legacy return values remain unchanged. The page and Worker loaders and simulation/evaluation source closures include the new shared dependency.

`st-obligation-resources.js` is an **unwired compact backend** over Route, not a second evolving ledger. It supplies the existing finite repair/search interface, count-aware uncertainty checks and honest disclosure of anonymous obligations. Successful compact proofs carry their endpoint uncertainty as well. Start consumes a literal current Context; Route alone adds public forced supply. Nested search and path checks continue the same fixed request root. A separate `fromProjection` entry deliberately creates a new hypothetical root, such as the maintenance request after a hypothetical handoff. It never imports that projection as actual state. The caller chooses a finite request horizon including nested work; exhaustion remains unfinished rather than a fabricated negative proof.

`st-opening-eligibility.js` replaces historical consumer queries with finite selectors. Two fixed account flags preserve the exact third-T retention window and the broader delayed-quality preference. Later Ts close the exact-third-T window without erasing a still-mandatory opening Z. Nonclear versus clearing Z retains the old count distinction. A source-profile violation can retire baseline eligibility while leaving the old consumer's quality preference active; the adapter preserves that existing quirk rather than changing policy. Full selectors require the current board and Center targets. The account payload is still experimental and unwired: earlier version-one snapshots without these required flags now reject rather than reconstruct missing history. Establish an explicit published format version/migration policy before wiring session transport. Already fulfilled conservation remains a short-circuit. Projected handoff stays immutable and in the hypothetical domain.

`st-obligation-tracking.js` is an **unwired observational subscriber boundary** over the supplied before/after current facts and this operation's effects. It checks classification/compaction and exact identity continuity, Center lifecycle, opening-duty changes, local Z conservation, Reset completion, availability and optional observed-projection consistency. It does not rerun the factual reducer as its own oracle or keep another evolving ledger. Deduplication retains current issues in fixed operation stages, not an archive of every past identity. Legitimate creation, payment, compaction and carried uncertainty emit no anomaly. Final status reads supplied authoritative current facts plus explicit caller coverage/censoring metadata. Unknown and unavailable remain distinct.

Focused fault tests deliberately drop duties or effects, replace equal-count identities, forge resolution labels, double-credit Reset, mismatch projection, and exercise handoff, observer isolation and issue resolution/reappearance. These diagnostics do not change route admission. No actual player/simulator subscription is switched yet; the old history-based monitor remains until current lifecycle, transport and consumers move together.

## Remaining migration and retirement order

The whole migration is not complete. Production still uses the legacy S/L and opening/Z/Reset authority, including its allocation tape and action/lock limits. Do not describe this checkpoint as cap-free resource accounting or completed trusted session import.

1. **Finish accepted-plan continuity and consumer integration.** Use the compact resource/search and opening adapters above in actual caller paths, and replace full-tape retention checks with bounded accepted-plan continuity. Preserve selected Left jobs independently from replaceable routes. Isolated adapter tests do not establish equivalence of all coach dispatch and retention paths.
2. **Move actual and coach consumers together.** Bind controller, worker and simulator transport to the shared state. Preserve finite opening-phase boundary facts, route spending permissions, Reset-completion effects, retained-plan continuity and policy-relevant canonical keys. Switch S/L, opening, Z and Reset readers only when their old identity-sensitive decisions have matching adapters and regression coverage.
3. **Finish durable Left goal ownership.** Retain the underlying current deficit separately from a replaceable checked repair plan. Do not generalize the existing D/J/L strategy as part of this migration. Reconcile equivalent goals so repeated advice cannot accumulate duplicates.
4. **Complete current session and Undo transport.** Import complete current facts directly; keep the old replay format only as a compatibility reader. Implement caller-owned inverse receipts, including provisional operations and sequential Undo, without embedding a receipt chain or piece history in shared state. Controller freshness and continuity checks must not become provenance requirements for trusted imports.
5. **Replace history-based monitoring and remove retired machinery.** Emit observational effects for actual transitions and report authoritative final status. Remove historical deletion scans, full-tape continuity checks, duplicate transitions and live resource caps once all their consumers are migrated. Keep deliberately finite legacy-format validation isolated from live state.

The paired transition, invariant, lifetime and public replay tests support these checkpoints. They do not establish equivalence for unimplemented admission/transport adapters. Test manifests and generated replay evidence are retained outside Git. The repository retains source, process documentation and deliberately minimized regression fixtures only.

No real-browser rendering or production-performance acceptance is claimed. Performance is monitored, with optimization deferred. The browser-free tests exercise the actual page and Worker loaders and controller behavior within the documented host limits.
